# Синтетическая протонограмма

Модель протонной радиографии мишени, по которой распределены заряд и ток.

1. Мишень задается кривой в плоскости x = 0 (окружность или "улитка").
   Кривая разбивается на отрезки, заряд делится по отрезкам пропорционально длине.
2. Из точечного источника на оси y методом Монте-Карло вылетают протоны
   со случайными углами и энергиями.
3. В слое `START_Y <= y < EXIT_Y` около мишени на протоны действует сила Лоренца.
   Поле E считается по закону Кулона, поле B по закону Био-Савара-Лапласа,
   движение интегрируется методом Бориса.
4. После слоя протоны летят прямо до экрана `y = SCREEN_Y`,
   точки попадания выводятся на график.

## Запуск

```
pip install -r requirements.txt
python main.py
```

Все параметры находятся в `config.py`.

## Файлы

| Файл | Что делает |
|---|---|
| `config.py` | константы и параметры расчета |
| `target.py` | формы мишени, разбиение на отрезки |
| `vec3.py` | операции над векторами для numba |
| `fields.py` | поля E и B в точке |
| `pusher.py` | шаг метода Бориса |
| `source.py` | генерация протонов |
| `simulation.py` | пролет через поля и перенос на экран |
| `plot.py` | график протонограммы |
| `main.py` | точка входа |

## Почему метод Бориса

Это стандартный метод для движения заряда в полях E и B.
Поля считаются один раз за шаг, точность второго порядка.
В магнитном поле метод только поворачивает вектор скорости,
поэтому модуль скорости сохраняется точно и энергия не "уплывает"
из-за ошибок счета, в отличие от метода Рунге-Кутты.

## Отличия от исходного скрипта protons_3.py

- e/m протона исправлено: было 0.9576e7, стало 9.58e7 Кл/кг.
  Из-за этого отклонения стали в 10 раз сильнее, и при прежних Q и I
  изображение выходит за старое окно 10 мм. Окно увеличено до 30 мм.
- Полный заряд мишени теперь ровно Q. Раньше плотность считалась
  по 48 отрезкам из 55, и заряд был в 55/48 раза больше.
- Модуль начальной скорости ровно v0, точка старта лежит на луче из источника.
- Скорость считается из энергии в МэВ, разброс энергии задается
  через `ENERGY_MIN` и `ENERGY_MAX`.
- Вместо псевдо-РК4 (поля один раз за шаг, координата по Эйлеру)
  используется метод Бориса.
- Расчет распараллелен с помощью numba, см. раздел ниже.
  Расчет занимает около 0.05 с вместо 57 с.
- Подпись графика строится из параметров, оси в миллиметрах.

## Распараллеливание

Протоны не влияют друг на друга, поэтому каждый протон ведется
целиком, от старта до вылета из слоя, в своем потоке
(`prange` в `simulation.py`). Потокам не нужно ждать друг друга
на каждом шаге, а все вычисления идут без выделения памяти:
векторы хранятся как кортежи (x, y, z).

Замеры на 3000 протонов (Ryzen 7 5700U, 6 потоков):

| Вариант | Время |
|---|---|
| numpy, все протоны массивами | 5.5 с |
| numba только для полей, цикл по шагам в Python | 0.92 с |
| numba, вся траектория в потоке, 1 поток | 0.18 с |
| numba, вся траектория в потоке, 6 потоков | 0.05 с |
| то же, но векторы как массивы numpy | 1.1 с |

Первый запуск дольше на 1-2 с из-за компиляции, дальше
скомпилированный код берется из кэша `__pycache__`.
Число потоков задается переменной окружения `NUMBA_NUM_THREADS`.

## Ограничения

Каждый отрезок мишени считается точечным зарядом и элементом тока.
Протон, пролетевший вплотную к центру отрезка, получает
нефизично сильный удар. Таких протонов единицы на тысячи, и на экран
они обычно не попадают. Если появляется сообщение
"Достигнут предел шагов", значит, такой протон застрял в слое.
